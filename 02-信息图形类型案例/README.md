## 三、本目录的三种组织维度

请勿将以下三个维度混为一谈：

1. **数据逻辑 / 信息架构**：说明信息之间是什么关系，例如编年、层级、编目、字母表和地理关系。
2. **信息图形表现类型**：说明案例主要以何种形式组织画面，例如混合型、文字/列表型、时间轴型、示意图型、流程图型、比较型、词云图型等。
3. **基础图形设计标签**：说明作品采用了什么可复用的视觉设计方法或符号系统。

## 四、ISOTYPE 标签规则

**ISOTYPE 不是信息图形的一种类型，而是一种基础图形设计方法 / 视觉表达方法。** 它可以被不同的数据逻辑和信息图形表现形式采用，因此单独作为横向标签管理，不加入01—20表现类型序列。

每个案例可以同时具有一个主数据逻辑、一个主表现类型，以及零个或多个基础图形设计标签。标签必须有案例证据支持；无法确认时标记“待核实”，不要仅因作品出现图标、插画或重复图形，就自动认定使用了 ISOTYPE。

## 五、与其他模块的关系

- [01-信息图形数据逻辑](../01-信息图形数据逻辑/README.md)：研究信息对象之间的关系。
- [03-统计图形分析](../03-统计图形分析/README.md)：独立研究案例中局部统计图表的数据输入、计算机制、视觉编码与选型；它不是案例的整页表现类型。

## 六、案例归档原则

- 每张原图只在“案例图”中保存一份，交叉类型通过索引引用，不重复存储。
- 每个案例分析文档放入“案例库”，使用 C001、C002……编号。
- 文件名记录类型缩写、编号、主题关键词与来源；原图、裁切图和标注图分别保存。
- 尽量记录来源、作者/机构、年份和原始链接；未知信息标注“待核实”。
- 案例分析区分可见事实、分析推断和待核实信息。
