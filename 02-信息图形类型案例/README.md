## 三、分类维度与归并边界

请勿将数据逻辑、视觉表现类型和基础图形设计方法混为一谈：

1. **数据逻辑 / 信息架构**：描述对象之间的关系，例如编年、层级、编目、字母索引和地理关系。
2. **视觉表现类型**：描述作品主要以什么视觉形式组织画面，对应本目录的17个文件夹。
3. **基础图形设计方法**：描述可复用的视觉表达方法，例如 ISOTYPE；它是跨类型标签，不另占本目录的表现类型编号。

原有“编目型”“字母表型”与“地理型”不再各自建立独立表现类型文件夹：编目与字母索引作为组织/检索规则，在以文字或条目为主要视觉结构时归入 **02 文字型列表型**，其他情况按主表现形式归档；地理关系作为数据逻辑保留，地图、地标或空间导航成为主要视觉形式时归入 **07 地标型 Location**。相关判断在案例索引中记录，不丢弃其分析维度。

ISOTYPE 仍作为基础图形设计方法独立研究，见[05-ISOTYPE信息图形设计](../05-ISOTYPE信息图形设计/README.md)。

## 四、案例归档结构

每个类型文件夹采用以下结构：

```text
类型文件夹/
├── 00-标签说明.md
└── 案例/
    ├── README.md
    └── CASE-XXXX-案例名称/
        ├── README.md
        ├── 分析.md
        ├── 原图来源.md
        ├── 原图.png / 原图.jpg（如已取得并可归档）
        ├── 数据集.csv（如有）
        └── 数据字典.md（如有）
```

每个案例只在一个主表现类型下保存一份。辅助表现类型、数据逻辑和设计方法作为标签写入案例 README 与全库索引，不复制案例文件。图片和数据资产优先放在对应 CASE 文件夹内，不另建与案例脱节的根级“案例资源”目录。

## 六、持续维护

1. 新案例先核验来源与权限，再分配唯一 CASE 编号。
2. 根据主要信息任务确定唯一主表现类型；辅助类型不重复归档。
3. 区分可见事实、理论依据、分析推断和待核实事项。
4. 若案例包含统计图形，记录数据字段、统计口径、计算方式、视觉映射和误读风险。
5. 完成分析后更新案例索引，并检查相关数据逻辑、统计图形和基础设计方法文档是否需要回写。
6. 移动文件后检查相对链接；不要为填充目录而虚构图片、数据、来源或授权状态。
