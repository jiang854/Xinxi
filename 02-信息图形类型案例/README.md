# 02 信息图形类型案例

本目录用于保存信息图形案例分析，并建立案例分类、表现形式和基础设计方法之间的关联。

## 本目录的三种组织维度

请勿将以下三个维度混为一谈：

1. **数据逻辑 / 信息架构**：说明信息之间是什么关系，例如编年、层级、编目、字母表和地理关系。
2. **信息图形表现类型**：说明案例主要以何种形式组织画面，例如混合型、文字/列表型、时间轴型、示意图型、流程图型、比较型、词云图型等。
3. **基础图形设计标签**：说明作品采用了什么可复用的视觉设计方法或符号系统。此类标签可以跨越多个信息图形类型，不作为新的信息图形类型。

## 基础图形设计标签

- **[ISOTYPE-基础图形设计](ISOTYPE-基础图形设计/README.md)**

**重要分类原则：ISOTYPE 不是信息图形的一种类型，而是一种基础图形设计方法 / 视觉表达方法。** 它可以被不同的数据逻辑和信息图形表现形式采用，因此单独作为横向标签管理，不加入表现类型编号序列，也不建立与“混合型、时间轴型”等并列的类型目录。

### 标签使用规则

每个案例可以同时具有：
- 一个主数据逻辑及若干辅助数据逻辑；
- 一个主表现类型及若干辅助表现类型；
- 零个或多个基础图形设计标签。

标签必须有案例证据支持。无法确认时标记“待核实”，不要仅因作品出现图标、插画或重复图形，就自动认定使用了 ISOTYPE。

建议在案例分析文档中统一写明：
- **基础设计方式标签**：ISOTYPE-基础图形设计
- **标签状态**：确认使用 / 疑似使用（待核实）/ 不适用
- **判断依据**：符号是否标准化、是否重复使用、是否与统计对象或数量建立明确映射。

## 案例分析与素材目录

- [案例分析](案例分析/)：存放逐个案例的分析文档。
- [案例图片](案例图片/)：按主要视觉表现类型归档案例原图。
- [ISOTYPE-基础图形设计](ISOTYPE-基础图形设计/README.md)：记录可跨类型使用的基础图形设计方法标签。

## 标签与类型的关系

一个案例可以同时被标记为某种信息图形表现类型，并采用 ISOTYPE 基础图形设计方法。例如，某个地理型信息图形可以用地图作为主要表现形式，同时用标准化、可重复的象形符号表达各地区的人口数量。此时“地理型”是信息组织/表现分类，“ISOTYPE-基础图形设计”是横向方法标签，两者不冲突。
