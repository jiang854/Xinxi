## 三、本模块的三种组织维度

请勿将以下三个维度混为一谈：

1. **数据逻辑 / 信息架构**：说明信息对象之间是什么关系，例如编年、层级、编目、字母表和地理关系。
2. **信息图形表现类型**：说明案例主要以何种形式组织画面，例如混合型、文字/列表型、时间轴型、示意图型、流程图型、比较型、词云图型等。
3. **基础图形设计标签**：说明作品采用了什么可复用的视觉设计方法或符号系统。

一个案例可以同时具有一种主要数据逻辑、一种主要表现类型，以及零个或多个基础图形设计标签。三个维度可以交叉使用，但不应互相替代。

## 四、ISOTYPE 标签规则

**ISOTYPE 不是信息图形的一种类型，而是一种基础图形设计方法 / 视觉表达方法。** 它可以被不同的数据逻辑和信息图形表现形式采用，因此单独作为横向标签管理，不加入01—20表现类型序列。

每个案例可以同时具有一个主数据逻辑、一个主表现类型，以及零个或多个基础图形设计标签。标签必须有案例证据支持；无法确认时标记“待核实”，不要仅因作品出现图标、插画或重复图形，就自动认定使用了ISOTYPE。

## 五、与其他模块的关系

- [01-信息图形数据逻辑](../../01-信息图形数据逻辑/)：研究信息对象之间的关系与组织逻辑。
- [03-统计图形分析](../../03-统计图形分析/README.md)：独立研究案例中局部统计图表的数据输入、统计计算机制、视觉编码与图表选型；它不是案例的整页表现类型。
- [04-Gestalt格式塔视觉组织原理](../../04-Gestalt格式塔视觉组织原理/)：研究视觉元素如何组织为群组、整体与图底关系，可用于分析不同信息图形类型的视觉组织方式。

## 六、案例图与案例分析的归档原则

1. 每张案例原图只在“案例图”中保存一份；交叉类型通过索引或案例分析文档引用，不重复存储。
2. 每个逐个案例分析文档放入“案例库”，使用C001、C002、C003……编号。
3. 类型说明文档使用01—20编号；分类总览、案例索引和案例分析使用各自明确的文件名，不混用编号体系。
4. 文件名尽量记录类型编号、案例编号、主题关键词与来源；原图、裁切图和分析标注图分别保存。
5. 尽量记录来源、作者/机构、年份、原始链接，以及课程讲次或页码；未知信息标注“待核实”。
6. 案例分析应区分可见事实、分析推断与待核实信息，不因视觉相似而擅自推定数据关系。
7. 新增案例时，先确定主数据逻辑、主表现类型与辅助设计标签，再将原图放入“案例图”、分析文档放入“案例库”，并同步更新相关索引。
