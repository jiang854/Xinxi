# 02 文字型/列表型信息图形（Informational / List Infographics）

> 状态：类型说明初稿；具体原则以用户提供的案例图分析为依据。当前尚无案例图。

## 1. 概念定义

文字型/列表型信息图形以文字信息、条目集合和可扫描的组织结构为主要内容，通过标题、短句、编号、项目符号、图标、色块、分栏和信息卡片，将知识、步骤、事实、建议或对象清单组织为易于浏览和记忆的视觉内容。

它不是把普通文字简单排进版面。关键在于文字经过筛选、压缩、分组和层级化，并通过视觉编码建立阅读路径。列表型强调多个并列条目；文字型范围更广，还可能包含解释段落、知识卡片和步骤说明。

## 2. 基本信息逻辑

常见信息单元：标题、导语、条目、分类标签、编号/顺序、解释/例证、来源/注释。

常见组织逻辑：
1. 并列罗列。
2. 分类列表。
3. 顺序列表。
4. 按明确标准排序的优先级列表。
5. 对照列表。
6. 问答或知识卡片。

编号不一定代表排名或重要性，需结合案例判断。

## 3. 统计图形与计算方式

通常以信息组织为主，不一定使用统计图表。可结合图标阵列、对照表、流程图、比例条、小型柱状图/点图和关键数字强调。

若出现数量、排名、百分比或比较结论，应记录来源、计算口径和统计范围。纯文字清单不应包装成统计结论。

## 4. 视觉编码方法

- **点、图标与编号**：图标快速识别条目主题；编号建立顺序和定位；同级条目保持相近视觉权重。
- **线与分隔**：分隔线帮助区分模块；箭头仅用于真实步骤、流程或关系。
- **面与版式**：色块、卡片、边框和留白建立分区；网格适合并列条目，单列适合顺序阅读，双栏适合对照。
- **色彩与文字**：颜色区分类别、状态或模块；标题、关键词、正文、注释建立层级；压缩文字不能改变原意。

## 5. 数据/信息架构

先确定列表组织依据：条目是否并列、是否分类、是否有顺序、是否需要比较、是否有优先级、是否需要索引。

常见结构：
- 标题 → 导语 → 分类标题 → 条目列表 → 补充说明。
- 核心数字 → 多个解释模块 → 来源注释。
- 步骤总览 → 分步说明 → 注意事项。
- 并列对象 → 统一属性 → 差异总结。

列表项目尽量保持语法结构一致；分类标准应清晰，避免重复归类而不作说明。

## 6. 视觉叙事架构

常见方式：
- 总览式：先给主题和结论，再展示条目。
- 扫描式：通过标题、关键词和图标快速浏览。
- 顺序式：按步骤、流程或编号阅读。
- 对照式：并列模块比较对象。
- 卡片式：每张卡片表达一个知识点，整体形成集合。

设计时明确读者最先看到什么、每个条目需读到什么程度，以及哪些内容可以略读。

## 8. 当前待验证假设

- 主要竞争力是信息筛选、结构清晰和快速扫描，而非图形复杂度。
- 视觉元素应帮助定位、分组和理解文字，而非纯装饰。
- 条目语法、长度和层级越一致，整体越容易阅读。
- 当列表包含时间、层级、地理或字母索引逻辑时，应标记辅助类型。
