## 二、三个分类维度

1. **数据逻辑/信息架构**：信息对象之间是什么关系，例如编年、层级、编目、字母表和地理关系。
2. **信息图形表现类型**：作品以什么视觉形式组织画面，例如流程图、时间轴、比较、地理型等。
3. **基础图形设计方法**：作品采用什么可复用的视觉方法或符号系统，例如 ISOTYPE。

三者可以交叉使用，不应混为同一分类序列。统计图形则作为数据计算与视觉映射的技术层单独分析。

## 三、案例分析方法

逐案分析采用 A–E 五维框架：A 数据逻辑；B 统计图形与计算；C 视觉编码；D 数据与信息架构；E 视觉叙事。分析时区分直接证据、观察记录、分析推断和待核实事项。

## 五、维护原则

1. 保留原始研究成果和来源，不以模板替换研究正文。
2. 原始数据、清洗数据和派生数据分离保存。
3. 文件使用相对路径引用；移动文件后检查关联链接。
4. 未核实内容明确标记，不虚构图片、数据、来源或授权。
5. 新案例应检查是否需要反哺类型说明、理论文档、统计分析和设计经验。
6. 目录调整与文档版本更新应记录在变更记录中。
7. 视觉风格档案与主题变量分离；主题迁移不得擅自覆盖已确认的 STYLE DNA。
8. 单图风格提取标记为初步档案，跨主题稳定性须经实际生成验证。
