## 研究原则

1. **案例先行，归纳原则。** 具体设计原则以用户提供的案例图为主要分析依据。通用理论用于建立初始观察框架，不替代案例证据。
2. **区分数据可视化与信息图形。** 数据可视化侧重数据映射、统计表达与探索；信息图形通常进一步组织信息层级、图形符号、视觉叙事和阅读路径。两者可以结合，但不能简单等同。
3. **区分事实、推断与设计建议。** 案例中的可见事实、对数据逻辑的合理推断、可迁移的设计方法分别记录；无法确认的数据来源或计算过程标注“待核实”。
4. **持续迭代。** 每新增案例，先分析并归类，再更新对应案例文档；当多个案例呈现稳定共性时，再提炼到理论文档。
5. **理论文档不存放案例图片。** 理论文档保留概念、方法和文字论述，通过相对链接关联案例说明和素材。

## 两类文档的职责

### 01-信息图形数据逻辑

建立五种信息组织逻辑的概念定义。每篇文档统一讨论基本数据逻辑、统计图形与计算方式、视觉编码、数据/信息架构、视觉叙事架构。理论文档不嵌入案例图片，只通过文内相对链接关联案例文档。

### 02-信息图形类型案例

按案例的主要视觉组织方式归档。每篇 Markdown 文档是对应类型的概念说明、案例分析和方法总结；同类型案例素材统一放入“案例图片”下对应编号的子文件夹。

案例不应只按外观分类，还要判断其核心信息关系、数据结构和阅读路径。一个案例可以标记多个相关类型，但应注明主类型与辅助类型。图片只在主类型目录保存一次，其他类型文档通过链接交叉引用。

## 新案例的分析与更新流程

1. 记录案例：分配编号，保存原图，记录来源、作者/机构、链接和日期。
2. 识别信息对象：提取主题、对象、指标、类别、地点、时间、单位和数据来源。
3. 还原数据逻辑：判断时间、层级、目录、字母索引、空间或混合关系。
4. 拆解图形方法：识别统计图形、符号系统、尺度、比例、色彩和标注方式。
5. 拆解信息与叙事架构：记录标题、导语、分区、阅读路径、重点、图例和结论。
6. 形成案例结论：区分案例事实、分析推断、可迁移方法和适用条件。
7. 更新案例文档与图片索引。
8. 当多案例支持某项规律时，再反哺理论文档。

## 版本与证据约定

- **案例观察**：能够直接从图像或来源材料中确认的事实。
- **分析推断**：根据视觉线索推测的数据结构或设计意图，需明确标注。
- **归纳原则**：由多个案例反复支持、具有一定稳定性的可迁移方法。
- **待核实**：图中没有提供足够证据的信息，例如原始数据、计算公式或数据采集方法。
