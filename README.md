# 信息图形研究与案例分析知识库

本仓库用于持续整理信息图形的数据逻辑、统计图形方法、视觉编码、信息架构与视觉叙事方法，并通过真实案例图不断验证、修订和扩展知识体系。

## 研究原则

1. **案例先行，归纳原则。** 具体设计原则以用户提供的案例图为主要分析依据。通用理论用于建立初始观察框架，不替代案例证据。
2. **区分数据可视化与信息图形。** 数据可视化侧重数据映射、统计表达与探索；信息图形通常进一步组织信息层级、图形符号、视觉叙事和阅读路径。两者可以结合，但不能简单等同。
3. **区分事实、推断与设计建议。** 案例中的可见事实、对数据逻辑的合理推断、可迁移的设计方法分别记录；无法确认的数据来源或计算过程标注“待核实”。
4. **持续迭代。** 每新增案例，先分析并归类，再更新对应案例文档；当多个案例呈现稳定共性时，再提炼到“01-信息图形数据逻辑”中的理论文档。
5. **理论文档不存放案例图片。** 01 文件夹仅保留概念、方法和文字论述，通过文内相对链接指向 02 文件夹中的案例说明与案例素材。

## 两类文档的职责

### 01-信息图形数据逻辑

建立五种信息组织逻辑的概念定义。每篇文档统一讨论：

- A. 基本的数据逻辑：数据对象、字段、关系、排序或空间结构。
- B. 统计图形与计算方式：可能借用的统计图形、度量、计算和归一化方法。
- C. 视觉编码：点、线、面、体、符号、色彩、尺度、纹理等如何映射信息。
- D. 数据/信息架构：内容如何分组、排序、分层、关联和导航。
- E. 视觉叙事架构：读者从哪里进入、按什么顺序阅读、如何理解重点与结论。

理论文档不嵌入案例图片，只通过相对链接关联 02 中的案例文档。

### 02-信息图形类型案例

按案例的主要视觉组织方式归档。每篇文档既是该类型的说明文档，也是持续累积案例分析、观察结论和设计方法的记录。

案例不应只按外观分类，还要判断其核心信息关系、数据结构和阅读路径。一个案例可以标记多个相关类型，但应注明主类型与辅助类型。

## 新案例的分析与更新流程

1. **记录案例**：为案例分配编号，保存原图或可访问的图片文件，并记录来源、标题、作者/机构、链接和日期（已知时填写）。
2. **识别信息对象**：提取主题、对象、指标、类别、地点、时间、单位、数据来源等可见信息。
3. **还原数据逻辑**：判断案例主要表达时间顺序、层级关系、分类集合、字母索引、空间关系，还是多种逻辑的组合。
4. **拆解图形方法**：识别统计图形、符号系统、图形语法、尺度、比例、色彩和标注方式；无法确认的计算不作臆测。
5. **拆解信息与叙事架构**：记录标题、导语、分区、阅读路径、重点、注释、图例和结论。
6. **形成案例结论**：区分“案例事实”“分析推断”“可迁移方法”“适用条件与局限”。
7. **更新案例文档**：将完整案例分析写入 02 对应类型文档；必要时建立交叉类型链接。
8. **反哺理论文档**：当案例证据支持、修正或推翻已有概括时，更新 01 对应文档，并注明依据的案例链接。

## 案例分析记录模板

每个案例尽量包含：案例编号与名称、来源、原图链接/文件路径、主类型与辅助类型、主题与核心信息问题、数据对象与字段、统计图形与计算方式、视觉编码、信息架构、阅读路径、叙事策略、可迁移方法、适用条件与局限，以及对现有原则的新增或修正。

## 版本与证据约定

- **初始框架**：尚未收到案例图时建立的工作假设，后续必须接受案例检验。
- **案例观察**：能够直接从图像或来源材料中确认的事实。
- **分析推断**：根据视觉线索推测的数据结构或设计意图，需明确标注。
- **归纳原则**：由多个案例反复支持、具有一定稳定性的可迁移方法。
- **待核实**：图中没有提供足够证据的信息，例如原始数据、计算公式或数据采集方法。

当前版本为初始框架。随着案例图增加，文档内容将持续迭代。
