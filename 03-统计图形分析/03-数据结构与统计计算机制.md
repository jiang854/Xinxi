# 03 数据结构与统计计算机制

本文依据 RAWGraphs Charts 的 `dimensions.js`、`mapping.js`、`render.js`、`visualOptions.js` 和示例配置，分析图表背后的数据处理过程。

## 1. 图表不是从外观开始，而是从数据字段开始

RAWGraphs 图表模块通常先声明可接受的数据维度，再将用户表格字段映射到这些维度。以条形图为例：

- `bars`：类别字段，必需。
- `size`：数值字段，可选，支持聚合，默认数值聚合为 `sum`。
- `color`：可选颜色维度，数值默认可求和，字符串/日期可用去重拼接。
- `series`：可选系列字段。

这种声明不仅是界面表单，还决定数据类型校验、是否允许多字段映射、是否执行聚合，以及默认聚合口径。

## 2. 五个关键处理环节

### 2.1 字段类型与维度约束

`dimensions.js` 常见属性：

| 属性 | 含义 |
|---|---|
| `id` | 图表内部使用的维度名称 |
| `name` | 界面显示名称 |
| `validTypes` | 可接受字段类型：number、date、string |
| `required` | 是否必需 |
| `multiple` | 是否可映射多个字段 |
| `minValues` | 多字段映射时的最少字段数 |
| `aggregation` | 是否允许聚合 |
| `aggregationDefault` | 不同字段类型的默认聚合方式 |
| `operation` | 常见为直接读取字段值的 get 操作 |

### 2.2 数据映射与分组

`mapping.js` 负责把表格记录转换为图表所需的对象。源码大量使用 D3 的 `rollup` / `rollups` 进行分组汇总，例如：
- 条形图：先按系列分组，再按类别分组。
- 折线图：按系列/线条和 X 值分组。
- 矩阵图：按 X、Y 组合分组。
- 层级图：按多个层级字段依次嵌套。
- 网络图：按 Source 与 Target 组合汇总关系边。
- 冲积图：对相邻两个阶段字段分别计算流量。

若映射为直接读取（如 `bubblechart`、`parallelcoordinates`、`ganttChart` 的部分维度），每条输入记录通常对应一个绘图对象，不会自动变成同一类的统计汇总。

### 2.3 聚合函数

仓库脚手架注释列出的聚合选项包括 `csv`、`csvDistinct`、`sum`、`mean`、`max`、`min`。实际默认值由每张图的维度定义决定，不能假设所有图表统一求和。

| 聚合方式 | 结果含义 | 使用前核对 |
|---|---|---|
| sum | 数值总和 | 单位是否可相加、是否重复计数 |
| mean | 算术平均 | 是否需要加权、是否存在极端值 |
| max / min | 最大值 / 最小值 | 是否在回答极值问题 |
| csv | 将值拼接 | 是否会造成标签过长 |
| csvDistinct | 去重后拼接 | 去重规则是否符合业务语义 |

重要区别：**“没有映射数值字段”并不总是等于“按记录数计数”。**

- 条形图：未映射 size 时，分组后的 `size` 使用 `v.length`，即记录数。
- 多级层级图（treemap、sunburst、circle packing、dendrogram 等）：未映射 size 时，叶节点大小通常以记录数作为默认权重。
- Alluvial diagram：未映射 size 时，流量使用该相邻阶段组合中的记录数 `v.length`。
- Arc diagram、Sankey diagram、Chord diagram：源码在未映射 size 时为每个已聚合的 Source–Target 关系赋值 1；不是把同一关系的原始记录条数直接作为权重。若需要频次，应明确映射数值或预先计算频次字段。

### 2.4 统计变换与布局算法

统计计算和图形布局是两个不同环节：

| 处理任务 | RAWGraphs 源码中的代表机制 | 结果 |
|---|---|---|
| 分类汇总 | D3 `rollup(s)` | 类别/系列的聚合值 |
| 时间排序 | 按 X、日期或开始时间排序 | 连续轴上的顺序 |
| 排名/堆叠 | D3 `stack`、order、offset | 堆叠区间或排名位置 |
| 分位数 | D3 `quantile` | Q1、中位数、Q3 |
| 分箱计数 | D3 `bin`、`hexbin` | 区间/六边形内的观测数 |
| 密度估计 | `d3-contour` 的 `contourDensity` | 二维点云密度等值轮廓 |
| 树形布局 | `d3.hierarchy`、`tree`、`cluster` | 节点层级坐标 |
| 矩形分区 | `d3.treemap` | 按权重分配矩形面积 |
| 圆形打包 | `d3.pack` | 嵌套圆布局 |
| 流向网络 | `d3-sankey` / `d3-sankey-circular` | 节点位置、流带宽度 |
| 几何分区 | `Delaunay` / `voronoi`、Voronoi treemap | 最近邻单元或层级剖分 |
| 凸包 | `d3.polygonHull` | 点集最小凸包 |
| 力导向避让 | `forceSimulation`、`forceCollide` | 点/标签减少重叠 |

这些算法并不都在计算统计指标。树布局、节点避让和 Voronoi 剖分可能只是把已存在的数据关系转换成可读的空间结构。

### 2.5 视觉尺度与编码

`render.js` 将数据转换为图形坐标和属性。源码中常见：
- `scaleLinear`：连续数值映射到位置、长度或宽度。
- `scaleTime`：日期映射到时间轴位置。
- `scaleBand` / `scalePoint`：类别的离散位置。
- `scaleSqrt`：常用于圆形/气泡半径，使面积随数值变化，而不是半径直接线性变化。
- 颜色比例尺：分类或连续数值的颜色映射。
- D3 的 `area`、`line`、`arc`：将数据点/角度/区间生成路径。

必须区分“映射变量”和“布局变量”。例如蜂群图的纵向位移用于减少点重叠，并不表示第二个测量指标；平行坐标图每个轴各自使用本轴数据范围，不代表不同指标原始单位相同。

## 3. 几类典型数据处理链

### 3.1 类别 → 汇总值 → 条形长度

`records → groupBy(category) → aggregate(value) → scale(value) → bar length`

适用于类别比较。需要记录聚合函数和是否有分系列；如果使用比例，必须额外定义分母，不能仅靠条形图自动推断。

### 3.2 多时间点 → 分组汇总 → 折线/面积

`records → groupBy(series, x) → aggregate(y) → sort(x) → line/area`

适用于时间或连续变化。需明确时间粒度、缺失时间点、同一时间点多条记录的聚合口径。折线连接是视觉连续性，不自动证明因果或连续观测。

### 3.3 多类别 → 堆叠变换 → 组成结构

Streamgraph 与 Stacked bar chart 使用 D3 stack 相关机制。堆叠的排序和 offset 会改变基线位置与阅读重点：
- None：不改变堆叠基线的普通堆叠语义。
- Expand：将每个 X 位置归一化为整体比例。
- Silhouette：将堆叠整体居中。
- Wiggle：调整基线以减少流带的视觉摆动。
- Diverging：使正负值从零基线向不同方向展开。

RAWGraphs 的 Streamgraph 和 Bump chart 对负数有显式限制；不能将它们当作任意正负数值的通用堆叠工具。使用 Expand 等归一化方式时，纵轴不再表示原始绝对值。

### 3.4 原始点 → 分箱/密度 → 聚集区域

- Hexagonal binning：按空间网格把点分入六边形，`bin.length` 表示该格点数。
- Contour plot：`contourDensity` 对二维点云进行密度估计，带宽参数会影响平滑程度。
- Violin plot：`d3.bin` 将单变量数值分箱，轮廓宽度由每箱记录数决定。

三者不能混称“热力图”：六边形图是格网计数；等高线图是密度估计；小提琴图是单变量直方分箱形成的镜像轮廓。

### 3.5 层级记录 → 叶节点权重 → 树形空间分配

层级图通常将多列字段映射为层级路径，再汇总叶节点的权重。未提供数值字段时，某些实现默认使用记录数；提供数值时则使用指定聚合。之后才进入 treemap、sunburst、circle packing 或 dendrogram 的空间布局。

因此，层级图中的面积、角度或圆大小是否代表数量，必须追溯到叶节点权重，而不能只看嵌套形状。

### 3.6 关系边 → 邻接结构/网络 → 连线宽度

Arc、Chord、Sankey 等以 Source–Target 关系作为输入。映射层负责汇总关系边；渲染层再构造节点、矩阵或 Sankey 网络。要区分：
- 节点的数量/大小；
- 节点的连接度；
- 边的权重/流量；
- 有向关系与无向关系。

边宽只有在映射了明确权重时才能解释为流量或关系强度。

## 4. 数据质量与计算口径检查

每个案例在制作前至少核对：

1. 记录单位：一行代表一个人、一个事件、一次交易，还是一个已经汇总的类别？
2. 唯一键：同一对象是否重复出现？重复记录是重复采集还是有效多次事件？
3. 分组字段：分组层级是否互斥？一个对象是否可能进入多个类别？
4. 聚合口径：sum、mean、count、max、min 是否符合研究问题？
5. 分母：占比、率、密度的分母是什么？时间窗口和地理范围是否一致？
6. 缺失值：缺失是零、未知、不适用，还是未采集？
7. 时间：日期格式、时间粒度、时区和排序是否统一？
8. 单位：数值字段是否同量纲？是否需要标准化？
9. 正负值：图表是否允许负数？是否采用零基线或发散布局？
10. 视觉尺度：圆面积、条形长度、角度、颜色深浅分别代表什么？
