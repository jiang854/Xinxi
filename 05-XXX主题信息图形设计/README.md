# 05｜XXX主题信息图形设计

本文件夹是一套可复制的主题信息图形设计项目工作区。每启动一个新选题，可复制本文件夹并将“XXX”替换为具体主题名称；原模板保留为母版，不直接混入具体项目资料。

## 工作流程

1. [01-前期调研](01-前期调研/README.md)：界定选题背景、研究问题、受众与使用场景，收集相关作品和参考资料。
2. [02-主题内容分析](02-主题内容分析/README.md)：与大模型协作，分析主题内容，判断数据逻辑、信息图形表现类型、视觉媒介与具体标签。
3. [03-数据搜集](03-数据搜集/README.md)：按公共数据集、文本文献、自建数据集三条路径搜集资料，并记录来源、许可与可信度。
4. [04-基础数据集构建](04-基础数据集构建/README.md)：清洗、拆分、标准化数据，建立字段字典和可追溯的基础数据集。
5. [05-叙事框架搭建](05-叙事框架搭建/README.md)：将字段组合成信息单元，确定核心叙事、阅读顺序和视觉层级。
6. [06-视觉编码](06-视觉编码/README.md)：将数据与信息关系转化为点、线、面、体、色彩、文字、图像、统计图形及 ISOTYPE 符号系统，重点探索设计表达。
7. [07-信息轮盘测试](07-信息轮盘测试/README.md)：预留测试流程、材料、记录和分析位置；具体测试方法与判定标准待后续共同定义。
8. [08-设计实施](08-设计实施/README.md)：完成版式、视觉稿、数据图形制作、输出交付和过程归档。

## 关键分类：分析时分开判断

主题分析不能只给作品贴一个笼统类型。建议分别填写以下维度，并注明判断依据：

- **数据逻辑**：编年型、层级型、编目型、字母表型、地理型，或多个逻辑组合。它回答“信息对象之间是什么关系”。
- **信息图形表现类型**：混合型、文字型/列表型、时间轴型、示意图型、流程图型、比较型、图片式、层级型、单一图表型、文字可视化、解剖剖析型、可视化简历型、手稿型、编年与编目混合型、3D、编目型、字母表型、地理型、词云图型等。它回答“信息以什么结构和方式呈现”。
- **视觉媒介与风格**：照片主导、插画主导、平面矢量、手绘、3D、拼贴、编辑设计、极简、档案感等。它回答“画面采用什么视觉语言”。“照片风格”不是数据逻辑；照片式信息图形可作为表现类型，摄影媒介也可作为视觉风格标签。
- **基础图形设计方法**：ISOTYPE、图标系统、符号编码、地图符号、图形化标记等。ISOTYPE 是基础图形设计方法，不等同于信息图形类型，也不是 ISO 标准。
- **统计图形**：如柱状图、折线图、散点图、面积图、词云图等，需判断其是否承担真实数据映射。词云可作为表现形式或局部图形模块，不能仅凭外观认定其统计含义。

每个判断应区分“主类型”“辅助类型”“候选标签”，并记录证据、置信度和待验证问题。

## 基础数据集的硬性规则

**一列只定义一种字段，一格只存放一个原子数据值。** 单元格可以是名义值、量化值、日期、图像文件路径或一个文本条目，但不能把多个独立值塞进同一格。

- 不要在一个单元格中写“北京、上海、广州”；应拆成多行或建立关联表。
- 经纬度建议拆为 latitude 与 longitude 两列；每个单元格只放一个数值。
- 一格放一个图像资产路径；同一对象有多张图时，另建图像资产关联表。
- 多标签、多作者、多地点等一对多关系，不用逗号拼在一个单元格中，改用独立关联表。
- 每个字段应有字段名、数据类型、单位/编码规则、来源和缺失值规则。

## 叙事框架的基本方法

基础数据集是原子字段的集合；叙事框架则通过字段组合建立信息单元。例如：

- 名称 + 纬度 + 经度 → 地图上的地点信息。
- 地区名称 + GDP数值 + 年份 → 特定年份的地区经济比较。
- 人物名称 + 出生日期 + 关键事件 → 人物生平时间线。
- 物品名称 + 类别 + 材料 + 图像路径 → 分类目录或图鉴。
- 关键词 + 词频 → 词云或关键词权重表达（必须说明词频的统计口径）。

字段组合应服务于明确的叙事问题，不是为了把所有字段都放进画面。

## 建议的项目推进顺序

前期调研 → 主题内容分析 → 数据搜集 → 基础数据集构建 → 叙事框架搭建 → 视觉编码 → 信息轮盘测试 → 设计实施。

阶段可以往返迭代：数据搜集可能改变主题判断，基础数据集可能暴露字段缺口，测试也可能要求重构叙事或视觉编码。每次迭代保留版本和决策记录。

## 项目启动

开始一个具体选题时，先填写[00-项目启动与阶段总表](00-项目启动与阶段总表.md)，再逐阶段推进。每一阶段的 README 说明该阶段目标、子文件夹用途、建议记录内容和阶段交付物。
