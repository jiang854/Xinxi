# 05｜ISOTYPE信息图形设计

> **模块定位：基础图形设计方法 / 视觉表达方法**
>
> ISOTYPE 是可跨不同信息图形表现类型使用的图像化信息表达方法，不是与流程图型、时间轴型、地理型等并列的表现类型。

本模块研究 ISOTYPE 的历史与文献、图符语言、视觉编码、数量表达、案例证据和设计实践。模块采用四个主题目录，并将概念定义与方法总览放在根目录。

| [02-图符语言与视觉编码](02-图符语言与视觉编码/README.md) | 图符语义、标准化、造型规范、视觉变量、数量映射、图例与符号规则 |

## 二、四个研究方向

1. **历史与文献**回答 ISOTYPE 如何形成、发展，以及理论和实践资料来自哪里。
2. **图符语言与视觉编码**回答符号代表什么、如何保持一致，以及数量如何映射为图像。
3. **案例研究**回答具体作品是否真正采用 ISOTYPE，判断依据和证据是什么。
4. **设计实践**回答如何建立可读、准确、可复用的符号系统，并验证其传播效果。

原有独立的「03-数量表达与符号规则」内容并入 **02-图符语言与视觉编码**，作为该主题中的数量映射与符号规则部分，不再保留单独的第五目录。

## 三、分类边界

分析案例时，分别记录数据逻辑、信息图形表现类型和基础图形设计方法。ISOTYPE 作为跨类型标签使用，不因作品出现统一风格图标、插画或 pictogram 就自动确认。

标签状态统一为：
- **确认使用**：有系统化图像符号语法，并且符号与统计对象、数量或分类关系存在明确映射。
- **疑似使用 / 待核实**：有图像统计特征，但数量单位、符号规则或来源尚不清楚。
- **不适用**：图像仅用于装饰、场景说明或单项识别，未形成图像统计系统。

详细定义、方法流程和判定标准见 [00-ISOTYPE概念与方法.md](00-ISOTYPE概念与方法.md)。

## 四、案例归档原则

- ISOTYPE 专题案例统一进入「03-案例研究」。
- 每个案例记录来源、作者/机构、年代、符号对象、数量单位、视觉规则、数据依据、授权状态和证据等级。
- 原图只归档一份；其他模块通过相对链接引用，不复制图片或案例正文。
- 对非 ISOTYPE 案例，可作为边界参照链接，不应为了填充案例目录而强行纳入。
- 尚未核实的来源、作者、数量规则和授权状态明确标注，不推测补全。

## 五、与其他模块的关系

- [02-信息图形类型案例](../02-信息图形类型案例/README.md)：提供不同表现类型的逐案研究；本模块只对其中具有 ISOTYPE 证据的案例建立专题分析或边界参照。
- [01-信息图形数据逻辑](../01-信息图形数据逻辑/README.md)：提供编年、层级、编目、字母表和地理等数据组织逻辑。
- [06-XXX主题信息图形设计](../06-XXX主题信息图形设计/README.md)：在主题项目的视觉编码阶段调用 ISOTYPE 方法；项目过程资料仍归项目目录，本模块维护可复用的方法与案例。

## 六、维护要求

1. 历史陈述应区分原始文献、学术研究和后续解释。
2. 符号规则必须说明对象语义、数量单位、比例和图例。
3. 数量映射应与原始数据口径一致，明确舍入、部分符号和误差处理。
4. 案例结论必须有可核验的视觉或文献证据。
5. 设计实践需保存测试条件、反馈、版本和修订理由。
6. 目录或文件移动后检查仓库内相对链接，并同步更新仓库首页及变更记录。
